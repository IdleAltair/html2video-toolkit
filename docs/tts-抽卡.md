# BreezeTTS 2 抽卡配音方法论

适用于单说话人中文口播：长稿（30 句以上）、要能整段直接铺在成片下面、允许人耳抽查。
结论来自 2026-10 这次 27B 视频的 36 句实践（成片 6:28），参数与判据都可以照抄。

## 1. 起服务（只有一条路）

- 权重 `../breeze-tts-2`，Python 环境 `$HOME/breeze-tts-env/.venv`。
- **全局只允许一个实例**：一份权重占 7.2 GB 显存、宿主 21 GB 内存开第二个会被 OOM 直接 SIGKILL。
- API 是**单请求锁**：并发调用返回 409 `An inference request is already running`；更坏的是锁被踩时返回的音频会截断、带底噪。所以：只用一条顺序管线，`workers = 1`。
- 启动后必须等 `/health` 返回 `ok` 再发请求；旧实例没死透时端口仍然能连上，所有请求会打到僵尸进程上（返回 409 或 0 字节），先 `pkill -f breeze_infer.api` 再起。
- 走本地回环要 `--noproxy '*'`；参考音频路径用 `$PROJECT_ROOT/...` 形式。

## 2. 参数表：哪个钮管什么

| 参数 | 用值 | 说明 |
|---|---|---|
| `text` | 一句一请求 | 整句直接读，不要按逗号拆 |
| `instruction` | 每句统一一句自然语言 | **唯一语速入口**，措辞影响极大（同一句 3.4 / 6.1 / 7.4 s）；缺省、空串、传了但不给内容都会 500 |
| `cfg_scale` | `4` | 上游默认 1.0；实测 1 / 2 / 4 差异在 ±0.5 s 内，定下就别来回换 |
| `seed` | 每句抽 3 个 | **句内节奏的主旋钮**：同句不同 seed，前后半句字速比在 0.69–1.61 之间，总时长只差 ±10% |
| `temperature` | 固定 0.9 | 硬编码，不可调（调 0.5 会退化成 15.6 s / 52% 静音） |
| `ref_audio` | 15–23 s 干净人声 | 超过 24 s 会被截；参考音频里有 BGM、气口会原样带进输出 |
| `ref_text` | 与参考逐字一致 | 错一个字，音色和断句都会飘 |

没有 speed / rate 参数。想让语速变，只能改 `instruction` 或换 seed。

## 3. 抽样与选片

1. **整句一次合成**。拆句（按逗号切）指标更漂亮，但听感会断；长句的节奏问题先靠抽 seed 解决。
2. 每句合成 3 条（seed 7 / 11 / 23），标不达标的句子再补 4 条（13 / 19 / 29 / 37）。
3. 逐条量三个数：时长、**字/秒**（只数汉字，英文和数字只作参考）、**最长空拍**（≥0.15 s 的静音段里最长的那个）。
4. 判据：`5.4 ≤ 字/秒 ≤ 7.8` 且 `最长空拍 ≤ 0.6 s`。排序时先满足判据，再按 `|字/秒 − 6.3|` 由近到远、空拍由短到长。
5. 25 字以上、专有名词密集的句子，7 个 seed 全在 4.2–6.0 之间是常态——这种句子交给耳朵，不要为了指标把它切碎。

实测成本（本机）：每句 3 seed 全片 108 条用了 2,446 s，平均 23 s 一条；36 句大约 40 分钟，全程可以挂后台。

## 4. instruction 梯度实测

同一组 13 / 20 / 46 字三句、seed 7、cfg 4，单位字/秒：

| 档 | instruction | 短 / 中 / 长 |
|---|---|---|
| A | 语速缓慢从容，吐字清晰，不赶时间。 | 6.70 / 8.07 / 4.45（长句 0.72 s 空拍） |
| E | 一字一句，从容不迫，语速放慢，吐字清晰。 | 6.52 / 5.85 / 5.94（空拍 ≤ 0.44） |
| X | 语速慢一点，再慢一点，从容不迫，吐字清晰，不赶时间。 | 4.27 / 3.73 / 4.57（刻意放慢，成片会拖） |

E 在长短句上都稳，是本机定档值；D（语速缓慢从容，吐字清晰，不赶时间。）在长句上会崩到 4.45 并甩出 0.72 s 空拍，不建议按字数分档混用。

## 5. 拼轨与对轴

- 每句按 RMS 归一到 −20 dBFS，峰值压到 0.99 以下，避免句子间忽大忽小。
- 句间留 **1.2 s**（听感：1.0 偏紧、1.4 偏慢），章节标题页需要 2.5 s 就位时，跨章间隔取 1.2 + 2.5 = 3.7 s。
- 字幕按最终稿**逐字照搬**，不要用配音改写稿：读音改写（千问、毫秒、八位整数）只喂 TTS，观众字幕保持原样。
- 页面 CUES 必须由时间轴反推：`页时长 = 下一页首句起点 − 本页首句起点`。不要用「本页末句结束 + 间隔」累加，否则章节页的 2.5 s 会被重复计入，整轨越放越漂。

## 6. 已验证不可行的路线

| 做法 | 结果 |
|---|---|
| `atempo` / librosa 拉伸修节奏 | 相位声码器把频谱重心 1399 → 1571 Hz，人耳判「糊」；只能做 ±10% 整体微调，修不了句内节奏 |
| 按逗号拆句再拼 | 指标更可控，听感断裂 |
| 聊天式 instruction（像跟朋友聊天） | 底噪 −61.6 → −51.6 dB |
| 不传 / 置空 instruction | HTTP 500 |
| temperature 0.5 | 6.40 s → 15.60 s，静音占比 23% → 52% |
| 并发发请求 | 409 + 截断 + 底噪 |

## 7. 判据的边界

字/秒与空拍只能筛掉明显崩坏的，**质感、句首切孤测不到**。经验值是这套判据筛出来的候选约 89% 人耳可用，所以：整批跑完后人工抽查 4 句（指标偏离最大的那几句）+ 整轨各抽一段，就够定稿。

参考实现（本项目）：`local-deploy-27b/tts/` 里的 `dub9.py`（合成 + 指标 + 断点续跑）、`finish9.py`（选片 + 拼轨 + 字幕 + CUES）、`script-v9.json`（36 句 sub/tts 双轨文本）。
