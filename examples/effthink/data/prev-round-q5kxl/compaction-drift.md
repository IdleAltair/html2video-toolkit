# 主动压缩有没有造成思维漂移 / 信息损失

**结论：有。折叠之后模型确实需要重新取证规则，代价可量化。** 但它不会去查会话历史，所以损失表现为"回源文件重读"，而不是"问系统要回原文"。

> 订正说明：本文档第一版曾给出"重读题目文档 0 次、未发现漂移"的结论，那是脚本口径错误造成的——统计时把"压缩前没有 `read` 类动作"当成了"没有重读"，而模型早期是用 `cat` 读题目的。现已按内容口径重做。

## 一、直接证据：圈地第三次折叠后立刻回读源文件

圈地全场 `read` 工具只被调用 6 次，**全部发生在第三次折叠（15:15）之后**：

| 时刻 | 步号 | 动作 | 当时的思考原文 |
|---|---|---|---|
| 15:16 | 1.72 | `read TASK.md`、`read engine/game.py` | "Now that the context has been organized, let me continue debugging the remaining issues…" |
| 15:16 | 1.73 | 再读 `engine/game.py` | "Let me read the engine's game.py to get an exact grasp of the rules — **I need the exact semantics of capture/cut**" |
| 15:16 | 1.74 | `read submission/bot.cpp` | "Now I've got a precise understanding of the rules. Key insights: 1. Death → teleport to spawn, trail cleared…" |
| 15:18 | 1.75 | `read anchors/greedy.cpp` | "Now I have the full picture. Let me analyze the weaknesses against the rules" |
| 15:26 | 1.76 | `grep -n "deadline\|time_limit\|move_ms\|timeout" engine/referee.py` | （逆向 greedy 的 makePlan，**独占 7.4 分钟**） |
| 15:35 | 1.84 | `read submission/bot.cpp`（带 offset 195） | 逐行核对 decide() |

1.72–1.76 这五步共约 10 分钟，全部内容都是"把规则、引擎语义、对手实现重新捞回来"。紧接着 1.77 它整份重写策略，1.80 成绩从 3:7 掉到 1:9（"Way worse! 1:9… There's something fundamentally broken."）。这两件事相邻，但**无法证明因果**——重写本身的倒退不能只归给折叠。

## 二、三条硬指标（重做后）

| 指标 | 圈地（4 次折叠） | 炸弹人（3 次折叠） |
|---|---|---|
| 回查被折叠的会话历史（`session_query`、读日志） | **0 次** | **0 次** |
| 折叠后回读题目/引擎/对手源码 | **6 次，集中在第三次折叠后** | 重读自己的 `bot.cpp` 共 6 次（1 / 1 / 4） |
| 折叠后重跑同一条命令 | 0 | 1（改完代码重新编译，必要动作） |
| 折叠后重做同一处编辑 | 0 | 1（收尾多版本对比） |
| 思考中出现"忘了 / 之前说过"类句式 | 1 处（实为排查管道无输出，与折叠无关） | 0 |

"从不回查历史"这一条仍然成立且关键：DSH 提供了 `session_query` 恢复工具，模型全程一次都没用。它丢失信息后的应对方式是**回到源文件重读**，而不是向系统要回原文。夺旗正式赛的对照实验（`billion-context` 论文 §8.1 用的正是 qwen3.8-27b）给出同向结论：这一档模型不会自发使用恢复工具。

## 三、压缩事件的真实归属

`compact_region` 在 `tool/call` 层为 0，只出现在 PTC 派发层——也就是说这些折叠是**模型自己主动发起**的，不是引擎按阈值强推的。逐次归属以 `compaction.md` 第三节为准（它按 `compactionId` 与 `compact-region-diag.log` 的 `folded:` 行一一对应）：

| 集 | 压缩次数 | 模型主动局部折叠 | 引擎整段接管 | 压掉并释放的 token |
|---|---:|---:|---:|---:|
| 圈地 | 4 | 4 | 0 | 239,742 |
| 炸弹人 | 3 | 2 | 1（18:12–18:16） | 186,040 |
| 夺旗 | 1（19:22） | 1 | 0 | 68,756 |
| **合计** | **8** | **7** | **1** | **494,538** |

订正：本文档早先版本记"夺旗 0 次折叠、两场合计 425,782"，那是 19:20 的旧采样；夺旗在 19:22 完成了自己的第一次折叠（区间 seq 9→128，30 个事件，释放 68,756 token）。另外早先"圈地 4 次整段压缩 + 4 次 compact_region"是把同一批事件按两个维度各数了一遍，实际圈地的引擎整段压缩为 0 次。

## 四、压缩税（两半）

**第一半：写笔记的时间。** 主动折叠不额外发推理请求，引擎落盘替换只有毫秒级；真正花掉的是模型自己想、自己写那段笔记的当步时间，实测区间 **32 秒 – 1 分 53 秒**（逐次：1 分 53 秒 / 51 秒 / 1 分 10 秒 / 32 秒 / 1 分 08 秒 / 1 分 31 秒 / 1 分 25 秒）。唯一那次引擎接管另有**摘要推理 3 分 56 秒**（含云端通道失败后回落本地 27B），是全场唯一有 token 记账的压缩：输入 9,582、缓存读取 96,497、输出 7,782。

**第二半：折叠后首步的重放。** 被折叠点之后的内容要重新喂进去，缓存命中普遍掉回只剩开头约一万 token：

| 压缩 | 折叠后首步 | 该步未命中缓存的新输入 token | 该步缓存命中 |
|---|---|---:|---:|
| 圈地 14:39 | 14:46 | **113,294** | 10,055 |
| 圈地 14:47 | 14:48 | 34,696 | 10,055 |
| 圈地 15:15 | 15:16 | 16,624 | 10,055 |
| 圈地 16:23 | 16:23 | 10,794 | 10,652 |
| 炸弹人 17:06 | 17:07 | 47,195 | 10,176 |
| 炸弹人 17:29 | 17:30 | 9,013 | 10,176 |
| 炸弹人 18:12 | 18:20 | 45,384 | 10,653 |
| 夺旗 19:22 | 19:23 | 38,284 | 10,118 |

注意这组是 **token 数不是秒数**——本场没有逐次重放耗时的记录。要折算成秒只能按 2026-09-30 自测的约 1000 token/秒 prefill 粗算，那是另一场会话的速率、属推算，视频里若给秒数必须标注。

摘要体量：圈地 4 次共 11,211 字，炸弹人 3 次共 16,770 字，夺旗 1 次 2,412 字（落盘）。

## 五、摘要保住了什么、丢了什么

对全部摘要做关键词检索（宽正则，中英文表述都算）：

| 约束 | 圈地摘要 | 炸弹人摘要 |
|---|---|---|
| 提交路径 `submission/bot.cpp` | 保住 | 保住 |
| 每回合 50 ms 预算 | 保住 | 保住 |
| 协议 stdin/stdout 格式 | 保住 | 保住 |
| 时限与剩余分钟（"33min used/120min hard stop"） | 保住 | 保住 |
| 已验证结论与测试结果 | 保住 | 保住 |
| 当前最强版本号 | 保住 | 保住 |
| **禁止联网** | **未出现**（联网/网络/network/internet/curl/wget/离线 全不命中） | 保住（"no network/other-AI/other-contestant data"） |

圈地摘要更短（11,211 字 vs 16,770 字），丢的正是禁网那条。丢了的后果没有显现：审计三场工具调用的完整参数，圈地唯一命中是写进 `bot.cpp` 的 C++ 变量名 `nc`（邻居计数）被按行首误判为 netcat，属假阳性；炸弹人和夺旗 CLEAN。禁网是靠首轮提示词建立的，不靠摘要反复提醒。

## 六、这套分析的边界

- 折叠后回读源文件是**信息需要重新取证**的证据，但不能直接等同于"能力下降"：它回读之后 1.89–1.93 反而打出了全场最好的爬升（4:6 → 7:3 → 8:2）。丢掉细节、再自己捞回来，这个循环本身是有效的，只是慢。
- 圈地混战实力值 −282、与 random 锚点（−286）几乎同分，而单挑正常。这个落差与折叠有没有关系，轨迹里既找不到支持也找不到反驳的证据，记为未定。
- 摘要内容是我能拿到的全部；被折叠掉、且模型没有再回读的原文，无法事后评估损失。
