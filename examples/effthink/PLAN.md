# arena-effthink 视频规划

一句话主题：**Coder390 这个主打省思考的微调模型，是不是在少想很多的同时把能力保住了。** 测它的尺子是一个开源赛事工程 arena 的三场比赛对抗赛，对照对象是 unsloth 官方原版基座的 Q5_K_XL 量化档。

## 背景（给没看过前情的人）

**测试项目**：arena（开源赛事工程）。参赛者写一个 bot 打三场比赛不同的游戏——圈地、炸弹人、夺旗。每场 90 分钟开发建议线、120 分钟硬停；交卷后追加 40 分钟「加时赛」窗口，让模型自己迭代那份代码。正式评测每场打一千多局，赛程用固定 seed 钉死。

**两个模型**（全片一律用名字指代，不用「上一轮 / 这一轮」——观众没看过前一次）：

- **Coder390** = Qwen3.8-27B-Coder390-EfficientThink，LynnStyle-Q4 + MTP，19.62 GB / 5.75 bit 每参数
- **Q5_K_XL** = unsloth 官方原版基座的 Dynamic 量化档（UD-Q5_K_XL），20.88 GB / 6.11 bit 每参数

两次评测跑在同一台机器（2 × 5060 Ti）、同一套 agent 外壳（dsh Web GUI + `ptc-local-concise` 预设）、同一份提示词上。参数量 27.321B、866 张量、65 层、MTP 全相同 → 微调没动架构，体积差纯粹是量化档差。

**两个重点的次序**：第一是这两个模型各自的规格与行为对照，第二才是它们跟 9–11 个云端模型同池对打的成绩。正赛与加时穿插在每场里讲，不单独开复盘页。

## 已定口径

1. 全片不给「哪个模型更强」的判决；收尾只回答「这一版相对原版舍弃了什么」——简单问题想得短、做得多，复杂问题该长考的那场没变短。
2. 一处诚实交代并上画面：**两次同时换了量化档和是否微调，所以分数差不能全记在微调头上**。
3. 画面一律用模型名指代，不出现「上一轮 / 本轮 / 这一轮」——`check.mjs` 有禁词断言守着。
4. 三场比赛尺度不同（两场是实力值、一场是归一化相对分），分数从不横向加总；合计只允许同单位（token / 请求数 / 分钟）。
5. 圈地的 0 分必须配一句「低于 greedy 锚点记 0，是钳位不是没得分」——DeepSeek 与神秘模型两行都是这种情况。
6. 停机补偿时长、计时器冻结实现一律不进视频/字幕/README，页面只标「崩溃 · 续跑」。
7. 三场比赛总览页用画廊式（当前场占主回放位、其余退到小位），不做旋转。

## 交卷页的两态（10-10 第七批）

三张交卷成绩页把表格与柱图放回同一页：'src/p_script.js' 里那页渲染成 '.panes' 两个 '.pane'，柱图态那个 div 带 'data-stage="2"' 与 'data-beat="N"'。'cuePlay' 在本页第 N 句开口时把 'data-stage' 写到页面上，CSS（'src/p_style.css' 末尾）负责表格淡出、柱图淡入。柱子换用 'growXb' 这个 keyframes 名——同名动画在属性切换时浏览器不会重播。

柱图态里的元素不参与「一句一个元素」的点亮（'cuePlay' 里按 '.pane.bb' 过滤掉），否则它们会占掉表格态的句序。'pipeline/layout.mjs' 一次量测覆盖两态（opacity 不改 rect），'PAGE_QS="stage=2&"' 可单独复量柱图态。实测交叉淡变约 420ms、反向对照（不动 data-stage 时始终停在表格态）见 'pipeline/probes/probe-pane.mjs'。

## 出片方式（10-10 改）

**不再用 CDP 逐帧渲染**（'record-deck.mjs' 只留着做动画自检）。正片走 'pipeline/record-obs.mjs'：OBS 的 obs-websocket（127.0.0.1:4455）远程开始/停止录制，NVENC 硬编，脚本用 'document.title' 建「窗口采集」并临时禁用显示器采集，起一个 '--kiosk' 的真 Chrome 打开 'index.html?cue=1&auto=1&clean=1&wait=1'（时间轴挂起），确认开录后调 'window.__startCue()' 让翻页从 0 跑。

跑之前只需要一件事：OBS 先起来并启用 WebSocket（工具 → WebSocket 服务器设置：启用 / 4455 / 密码）。脚本会等页面 'document.hasFocus()' 最多 90 秒才开录；实测 '--kiosk' 全屏窗口自己就带焦点，不需要人去点。命令形如 'node pipeline/record-obs.mjs --password <OBS 密码> --seconds 626'（片长以 'data/cues.json' 为准，别沿用旧数字）。

气口口径：**句间 0.6s、换页 1.0s**（'pipeline/dub.py' 的 'GAP' / 'PAGE_GAP'，'dub_preview.py' 同步）。换页值必须大于播放器的翻页提前量 'CUE_LEAD=0.55'，否则会先开口再切页。成片音轨 'dubbing/deck_audio.wav' 按 'cues.sentences[].start' 逐样本落位，长度与 'cues.total' 相等（'python3 pipeline/join_preview.py'）；每句首尾各做 'FADE_MS=2' 的线性淡变 —— TTS 片段有 4 句以非零样本起收（句 95 首样本 0.186、句 84 末样本 0.151），直接落进静音就是阶跃，会出咔哒。淡变长度是量出来的：2ms 已把全片句边界最大台阶压到 0.00006、窗内新增单样本跳变 ≤0.009（语音自身可达 0.79），而 dsh 用的 8ms 会把句 95 的塞音起始削掉 0.51（约 11 dB）。配乐用 'python3 pipeline/mixdeck.py' 叠（人声 'loudnorm I=-16:TP=-1.5'、BGM '-13dB' + 70–13000Hz 带通、'sidechaincompress' 避让、'amix=normalize=0'）。

音轨贴回录屏与字幕烧录合成一步：'python3 pipeline/compose.py --video <OBS 录的 mkv>'，链复用 dsh 的 '.arena-preview.py'，只去掉它的 retimed —— 那步是修 CDP 抓屏帧率漂移，OBS 的 NVENC 恒定帧率不需要。字幕由 'pipeline/mksub.py' 按 cues 的逐句轴出 ASS（106 句拆成 124 条），'ass=' 滤镜烧进画面，'fontsdir' 指 'assets/'；几何为 PlayRes 2560×1440 + 'WrapStyle: 2' + 字号 68 + 'MarginV 20'，字幕顶边落在画面 86.8%，让开页面底部 tagline 约 45px（76/60 那版会压住第 5/24/25 页的 tagline）。实测：OBS 录出来的音轨是 -91 dB 数字静音（Chrome 带 '--mute-audio'），所以配乐不会重复；成片音轨综合响度 -16.6 LUFS，单声道（'sidechaincompress' 会把链塌成 mono，口播人声居中本就是标准做法；'pan=stereo|c0=c0|c1=c0' 显式复制是为了绕开 ffmpeg 上混凭空 ÷√2）。

## B 站封面（`cover/`）

上传一张 1920×1080，B 站会同时展示**首页推荐位 4:3** 与**个人空间 16:9**，4:3 是从这张图按中心裁左右 → **关键内容必须落在 x 240..1680**（水平中央 75%）。画面：标签行 + 标题 + 钩子「思考量 −24%，能力<u>掉没掉？</u>」（后三字做成琥珀底反白块）+ 三块事实卡（3 场算法比赛 / 3,464 局 / 2×5060 Ti）+ **底部一条 VS 对照**（`Q5_K_XL` 近白字水青边 · unsloth 原版 Dynamic 量化档 ｜ VS ｜ `Coder390 Q4Lynn` 红字红边 · post-train 微调 思考量 −24%）—— 用户要求把对照模型也凸显出来，对照关系本身就是卖点。做法：`cover/cover-src.html`（沿用工程配色与 Noto Sans SC）→ `node cover/build-cover.mjs` 把两枚 woff2 base64 内联成自包含页、无头 Chrome `--screenshot` 出 `bilibili-cover.png`，再用 ffmpeg 出 `preview-4x3.png`（中心裁）、`preview-4x3-small.png`（480×360，模拟首页小图看可读性）、`guide.png`（带 4:3 安全区参考线）。
页面自带一段 `load` 自检（量 `.top/h1/.hook/三卡/卡内 p/VS 两块/.badge` 的边界，判越界、两两重叠、三卡是否等高、卡内是否恰好两行，并算 WCAG 对比度比值），结果塞进隐藏的 `<pre id=metrics>`，构建脚本用 `--dump-dom` 读出来，任一问题直接 throw。**居中文本必须用 `Range.getBoundingClientRect()` 量字形**，量容器盒会假报越界（容器是故意放宽做居中的）。这条守卫做过反向验证：把 `h1` 字号从 88 撑到 200，自检如实报 `OUT-OF-4:3 h1` + `OVERLAP .top x h1` + `OVERLAP h1 x .hook` 三条。

**它当场抓到两个真 bug，值得记住**：① 封面 `:root` 漏定义 `--deep/--q5/--q5ot`，于是 `color:var(--deep)` 静默继承成白色，黄底上压白字实测 **1.62:1**（CSS 变量写错不会报错，只会悄悄回落到继承值——用对比度判据才看得见）；② **信号红 `#ff3b30` 压在钴蓝底 `#0f2ab0` 上只有 2.99:1**，同一红在深蓝面板 `#081238` 上有 5.13:1。用户两次说"区分度不够"（第 21 页三卡、这次封面的「掉没掉？」）物理原因就是这个：**强调色的可读性取决于它落在哪种底上，同色不同底差一倍**。封面因此给压在钴蓝底的大字另设 `--red-hi:#ff5f4a`（3.53:1），面板上的红保持 `--red`。**正片页面里 `--red` 直接压在钴蓝底的地方同样是 2.99:1，本轮没动正片**（要改得连整片一起重录），下次若用户再提"看不清/区分度不够"，先量比值再改色，别凭感觉换色相。

一处已知判据缺口：'layout.mjs' 的「内容压进字幕安全区」只量页面自带的内容，管不到后期烧进来的 ASS 字幕——它是按 cues 的时间轴在画面上叠加的，版式闸门看不见。所以字幕几何改动只能靠抽帧复验（`pipeline/p2/verify-final3.py` 末段：抽 6 个句子中点帧、裁画面底部 40% 拼一条带子，逐格核对字幕顶边与 tagline 的间距）。

两条量测口径上的教训（成片终检时踩到的）：
- **「句边界台阶」只能在纯人声轨 'deck_audio.wav' 上量**，在成片上量会得到假读数（实测 0.19977 @30.1s）——成片的句"间隙"里铺着连续 BGM，量到的是配乐波形而不是阶跃。同理，「相对局部基线的孤立尖峰」在语音上也不是判据（8668 处"尖峰"全是塞音/擦音的自然起始）。去咔的验收只认纯人声轨上那一条：最大台阶 0.00006。
- **成片走了两代 AAC**（'deck_mix.m4a' → compose 再编一次）。实测逐样本差 RMS -73.8 dBFS、相对信号 SNR 57.3 dB、互相关零偏移，远低于可听阈，因此不为省这一代编码改成 '-c:a copy'（那会让 '--audio' 传 wav 时直接失败）。'loudnorm' 也实测无群延迟（0 样本），不会让字幕比人声早。

clips.json 一放进来，第 3 页与三张「加时终版成绩」页与三张交卷页的视频槽就会从「待录屏」变成真画面，不用改代码。
